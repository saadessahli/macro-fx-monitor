# Contributing

Contributions are welcome.

1. Create a focused branch.
2. Keep changes scoped to one concern.
3. Run `npm run check` before opening a pull request.
4. Explain the user-facing effect and any data-source implications.
5. Do not commit credentials, generated builds, or downloaded research pages.

Data-source changes must document the provider, update cadence, attribution,
fallback behavior, and redistribution constraints.
